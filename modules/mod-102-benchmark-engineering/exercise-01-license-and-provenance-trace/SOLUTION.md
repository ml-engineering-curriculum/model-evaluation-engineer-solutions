# exercise-01 — License and Provenance Trace — Solution

## 1. Solution overview

The exercise asks the learner to produce a **per-item provenance trace** for a benchmark they plan to publish or depend on, and to translate that trace into a **go / no-go license decision** for the intended use (internal evaluation, external leaderboard, redistribution of the benchmark, or redistribution of model outputs scored against it).

The reference answer has three deliverables:

1. A **provenance schema** — one row per data component with the fields an auditor would need to re-derive the dataset.
2. A **worked trace** on a realistic composite dataset (example: a QA benchmark built from Wikipedia + CC-licensed books + synthetic LLM generations).
3. A **license decision matrix** that maps the trace onto a specific intended use, plus the refusal / mitigation path for incompatible items.

This maps to the NIST AI RMF `MAP` and `GOVERN` functions, which direct teams to "map" the context of use and to "govern" third-party data via documented policies and lineage ([NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)). It also hardens two attacker-visible surfaces called out by OWASP ML Top 10 and MITRE ATLAS: **ML06 Corrupted Packages** (unknown-origin artifacts carrying hostile code or terms) and **ML Supply Chain Compromise** on ATLAS (hostile data / model substitution) ([OWASP ML Top 10](https://owasp.org/www-project-machine-learning-security-top-10/); [MITRE ATLAS](https://atlas.mitre.org/)).

## 2. Implementation

### 2.1 Provenance schema

One row per *source component* (not per row of data — the point is to make the sub-licenses explicit). The following schema is sufficient for a benchmark governance review:

```yaml
# provenance.yaml — one entry per source component
- component_id: wiki-2023-10-dump
  description: "Wikipedia articles used as context passages."
  acquisition:
    method: "Downloaded from https://dumps.wikimedia.org/"
    acquired_on: "2026-01-15"
    acquired_by: "data-platform-team"
    checksum_sha256: "<sha256 of the exact dump file>"
  upstream:
    canonical_source: "Wikimedia Foundation"
    canonical_url: "https://dumps.wikimedia.org/enwiki/20231001/"
    source_version: "enwiki-20231001"
  license:
    spdx_id: "CC-BY-SA-3.0 AND GFDL-1.3-or-later"
    notice_text_path: "licenses/wikipedia-notice.md"
    attribution_required: true
    share_alike: true
    commercial_use_allowed: true
  transformations:
    - "HTML-stripped via wikiextractor v3.0.6 (configured to drop tables)."
    - "Articles filtered to pages tagged en-wiki stable."
  derived_items_count: 12488
  pii_assessment:
    contains_pii_at_source: "Possible (biographical articles may contain names, DOBs)."
    pii_handling: "Retained; dataset marked public-facing-only. No new PII added."
  risk_flags:
    - "share_alike: downstream users of the benchmark must honor CC-BY-SA on redistribution."

- component_id: synthetic-gpt4-questions
  description: "QA pairs generated by prompting a closed-weights LLM over Wikipedia passages."
  acquisition:
    method: "API calls logged to logs/gen-2026-01-18.jsonl"
    acquired_on: "2026-01-18"
    acquired_by: "eval-team"
  upstream:
    canonical_source: "<vendor name> API — <model id>"
    canonical_url: "<vendor terms of service URL>"
    source_version: "<model id and dated snapshot>"
  license:
    spdx_id: "LicenseRef-vendor-tos"
    notice_text_path: "licenses/vendor-tos-snapshot-2026-01-18.md"
    attribution_required: false
    share_alike: false
    commercial_use_allowed: "<depends on specific ToS — see notice file>"
  transformations:
    - "Prompt template stored in prompts/qa_v1.md (hash abc123)."
    - "Rejected generations stripped by the adjudication step in exercise-02."
  derived_items_count: 12488
  pii_assessment:
    contains_pii_at_source: "Not expected; passages were sampled from Wikipedia."
    pii_handling: "Scanned via regex + NER sweep; 3 items quarantined."
  risk_flags:
    - "ToS may forbid using outputs to train competing models — check 'competing model' clause."
    - "ToS may forbid benchmark redistribution of raw outputs."
```

Why these fields:

- `checksum_sha256` + `source_version` make the trace **reproducible**. Without them, "we pulled Wikipedia" is not a provenance record, it is a rumor.
- `spdx_id` is a machine-readable license identifier; free-text "MIT-like" is not auditable.
- `transformations` are what let a reviewer decide whether the dataset is a *derivative work*. Share-alike licenses care about this.
- `pii_assessment` is a safe-harbor artifact. Every source gets a pass even if the assessment is "no PII expected."
- `risk_flags` is the human-readable "what will trip us up at merge time."

### 2.2 License decision matrix

For an intended use, walk each component against four gates. A single **No** on any gate blocks that use.

| Gate | Question | Pass if |
|---|---|---|
| G1 Attribution | Does the intended distribution carry the required attribution / notice file? | License permits the medium or we ship the notice. |
| G2 Share-alike | Does the intended output license absorb the most restrictive share-alike? | Benchmark is published under a compatible copyleft, or none of the components are share-alike. |
| G3 Commercial / field-of-use | Does the license permit the intended use (commercial eval, paid leaderboard, academic-only, no-training-competing-models)? | No field-of-use clause is violated. |
| G4 PII / lawful basis | Is processing compatible with the lawful basis under which the data was originally collected? | Source permits the processing, PII was removed, or a lawful basis exists. |

Worked example — the composite dataset above, with four intended uses:

| Intended use | G1 Attribution | G2 Share-alike | G3 Field-of-use | G4 PII | Decision |
|---|---|---|---|---|---|
| Internal eval, closed network | Pass (notice bundled) | Pass (no external redistribution) | Pass | Pass (PII sweep clean) | **Allowed.** |
| Public leaderboard, read-only | Pass (notice on site) | Pass (we publish benchmark as CC-BY-SA-4.0 or 3.0) | Needs check on vendor ToS re: public display | Pass | **Allowed if vendor ToS permits public display of outputs.** |
| Redistribute full dataset for download | Pass | Pass if we license the derived dataset share-alike-compatibly | **Likely blocked** — many vendor ToS forbid redistribution of raw outputs | Pass | **Blocked** until synthetic component is regenerated under a model whose ToS permits redistribution, or until that component is replaced with human-written questions. |
| Train a model on the dataset | Pass | Pass | **Blocked** if the vendor ToS forbids using outputs to train "competing models" | Pass | **Blocked** or scoped (training allowed only for non-competing models, per ToS). |

### 2.3 Refusal and mitigation path

When a gate fails, the reference answer does *not* delete the row — it records the failure so that a later reviewer can see the decision trail.

```markdown
## Blocked distribution — 2026-02-01
- Component: `synthetic-gpt4-questions`
- Intended use: full-dataset redistribution
- Failing gate: G3 (vendor ToS §4.2 forbids redistributing raw model outputs)
- Mitigation taken: Rebuild the synthetic split under <open-weights model> (component_id: `synthetic-openweights-questions-v2`) and reserve the original split for internal use only.
- Reviewer: <name>, <date>, <PR link>
```

## 3. Validation steps

A learner should be able to answer **yes** to every item below using only the trace they produced.

1. **Reproducibility check.** For each component, can you re-download / regenerate the data using only the fields in the trace? If any component is missing a URL, version, checksum, or prompt hash, the trace fails.
2. **SPDX parse.** Every `license.spdx_id` must parse against the SPDX license list, or start with `LicenseRef-` and point to a committed notice file. Reject free-text fields like "Apache-ish."
3. **Attribution dry-run.** Render the attribution bundle that would ship with the benchmark. Confirm every required notice appears exactly once.
4. **Share-alike inference.** Run the matrix in §2.2 against four intended uses and show your work. The learner should be able to name the *most restrictive* share-alike constraint across all components without re-reading the trace.
5. **PII sweep evidence.** Each component shows a documented assessment (not "none" with no method). A regex sweep + a NER pass is the floor. Items flagged must have a committed quarantine action.
6. **Negative test.** Introduce a synthetic "poisoned" component (license: `LicenseRef-unclear`, no checksum, no attribution text). The matrix must block it out of every intended use.

## 4. Rubric

Scored out of 10. The rubric rewards the trace being *decision-grade*, not merely present.

| # | Criterion | Points | Passing evidence |
|---|---|---|---|
| R1 | Schema is reproducible | 2 | Every component has a URL or acquisition method + a checksum/version. A reviewer can re-derive the component without asking the author. |
| R2 | License identifiers are machine-readable | 1 | Every `license` field is a valid SPDX id or an explicit `LicenseRef-*` pointing to a committed notice. |
| R3 | Transformations are enumerated | 1 | Each component lists the derivation steps (tooling + config / prompt hash). "Cleaned up" is not a transformation. |
| R4 | PII assessment is a method, not a guess | 1 | Each component states the technique used (regex sweep, NER, manual audit) and the number of items flagged. |
| R5 | License decision matrix covers at least four intended uses | 2 | Internal eval, public leaderboard, dataset redistribution, model training — each with G1–G4 verdicts. |
| R6 | Share-alike and field-of-use failures block the use | 1 | At least one of the four uses is correctly blocked and names the exact clause. |
| R7 | Refusal path is written down | 1 | Blocked uses have a dated mitigation record identifying the component, failing gate, and chosen remedy. |
| R8 | Risk flags are specific | 1 | Each `risk_flags` entry names a concrete downstream obligation (e.g. "share-alike propagates to users", not "watch out for licensing"). |

**Passing bar:** 7 / 10. Below that, the trace is a decoration rather than a control.

### Review checklist (for a maintainer)

- [ ] Every component appears both in the trace and in the directory listing of the benchmark artifact.
- [ ] No component uses the string `"TBD"`, `"unknown"`, `"various"`, or an unresolved URL.
- [ ] The most restrictive share-alike license is named in the summary section.
- [ ] Vendor ToS files are *snapshotted* into the repo (ToS pages change silently).
- [ ] The matrix explicitly lists the intended uses that are blocked, not only the ones that pass.

## 5. Common mistakes

- **Treating "found on HuggingFace / Kaggle" as the source.** The platform is a mirror. The canonical upstream is the thing whose license governs — sometimes those disagree, and the stricter one wins.
- **Omitting the vendor ToS for synthetic data.** Generations from a commercial LLM are governed by that provider's ToS. Attaching an SPDX open-source license to that split is wrong.
- **"CC-BY" without the version.** `CC-BY-3.0`, `CC-BY-4.0`, and `CC-BY-SA-*` are different licenses with different notice obligations. Record the version.
- **Hand-waving PII.** "No PII expected" with no method is not an assessment. The sweep is cheap; the audit is not.
- **Tracking the dataset but not the transformations.** A reviewer needs to know whether the shipped artifact is a derivative work. "Dropped bad rows" is not enough; cite the script and config hash.
- **Trusting a prior trace.** License terms, ToS, and even SPDX identifiers change. Re-check at every version bump (see exercise-04).
- **No negative test.** If the trace never *blocks* anything, it is a sticker, not a control.

## 6. References

- NIST AI Risk Management Framework — <https://www.nist.gov/itl/ai-risk-management-framework>. In particular the `GOVERN` function on third-party data policies and documentation, and the `MAP` function on context-of-use. Used to motivate why a trace plus a decision matrix is the minimum artifact.
- OWASP Machine Learning Security Top 10 — <https://owasp.org/www-project-machine-learning-security-top-10/>. ML06 (Corrupted Packages) is the attacker surface a provenance trace closes: unknown-origin artifacts with hostile terms or payloads.
- MITRE ATLAS — <https://atlas.mitre.org/>. The ML supply-chain tactics describe why dataset lineage is a hardening target, not a compliance nicety.
- SPDX License List — <https://spdx.org/licenses/>. Canonical registry for machine-readable license identifiers used in the schema.
