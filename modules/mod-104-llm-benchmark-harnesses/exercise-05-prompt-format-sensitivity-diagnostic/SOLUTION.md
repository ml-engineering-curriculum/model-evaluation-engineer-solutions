# exercise-05 — Prompt-Format Sensitivity Diagnostic — Solution

## 1. Solution overview

The exercise asks the learner to build a diagnostic that **measures how much a model's benchmark score depends on the prompt format**, holding the underlying items constant. Reported LLM benchmark numbers are often fragile to superficial prompt choices — the newline between question and answer, the capitalization of the option labels, whether few-shot demos are present, the exact phrasing of the task instruction — and a single-format score cannot distinguish "the model knows this" from "the model happens to like this phrasing."

The reference answer has four deliverables:

1. A **format matrix** — a committed list of prompt-format axes and the levels each axis takes.
2. A **fixed evaluation set** — the same items evaluated under every combination of format levels. This is the core of the diagnostic: *the only thing that moves is the format*.
3. A **sensitivity report** — point estimates, CIs, and a decomposition of the score variance attributable to format vs. items.
4. A **decision rule** that turns sensitivity numbers into either a published "baseline + sensitivity band" result card or a refusal to ship until formats stabilize.

This maps to the NIST AI RMF `MEASURE` function, which requires measurements to be "reliable under non-material perturbations" to be fit for use ([NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)). A model whose score moves 8 points when you change `Answer:` to `A:` is not reliably measured; the sensitivity diagnostic is the evidence. The adversarial lens is OWASP ML Top 10 **ML01 Input Manipulation** — the attacker's cheapest tactic is to rephrase a prompt, so a model that is prompt-format-brittle in testing is also prompt-manipulation-brittle in production ([OWASP ML Top 10](https://owasp.org/www-project-machine-learning-security-top-10/)). MITRE ATLAS `Craft Adversarial Data` and `Evade ML Model` are the attacker techniques that the diagnostic surfaces as a *baseline* — if the model is this brittle to random formatting, intentional format attacks are easier still ([MITRE ATLAS](https://atlas.mitre.org/)).

## 2. Implementation

### 2.1 Pick the axes

The matrix is deliberately small — a full crossing of 8 axes blows up to 256 cells and nobody reads the result. Pick 4–6 axes that are *superficial* (should not matter to a truly competent model) and commit them.

```yaml
# formats/axes.yaml — committed matrix
axes:
  instruction_phrasing:
    - "answer_only:   'Answer:'"
    - "pick_one:      'Pick one of the options:'"
    - "best_answer:   'What is the best answer?'"

  option_label_style:
    - "upper:         A B C D"
    - "lower:         a b c d"
    - "parens:        (A) (B) (C) (D)"

  option_separator:
    - "newline"
    - "comma"

  fewshot_count:
    - 0
    - 5

  whitespace:
    - "tight:    one newline between fields"
    - "loose:    blank line between fields"
```

Rule: **every axis level is a named string**, not a position in a list. A later reader must be able to say "the drop was between `pick_one` and `best_answer`" without opening the code.

The full matrix is `3 × 3 × 2 × 2 × 2 = 72` cells — enough to detect a real sensitivity, small enough to fit on one page.

### 2.2 Fix the items and the seed

Pick a single dataset split and a single seed. The diagnostic is only meaningful if all 72 cells evaluate the *same* items in the *same* order with the *same* model weights.

```yaml
# formats/eval_fix.yaml
dataset:
  path: "<task>"
  split: "validation"
  item_count: 500
  checksum: "<sha256>"
model:
  id: "<org>/<model>"
  revision: "<sha>"
  dtype: "bfloat16"
decoding:
  temperature: 0.0
  do_sample: false
  seed: 1234
bootstrap:
  n_resamples: 10000
  seed: 1234
```

### 2.3 Render the prompts

The prompt is generated by a pure function `render(item, format_cell) -> str`. The function is a few dozen lines of string manipulation, but committing it is non-negotiable — it is the artifact the sensitivity is measured against.

```python
# formats/render.py
from dataclasses import dataclass


@dataclass(frozen=True)
class FormatCell:
    instruction: str          # one of the instruction_phrasing values
    label_style: str          # "upper" | "lower" | "parens"
    separator: str            # "newline" | "comma"
    fewshot: int              # 0 | 5
    whitespace: str           # "tight" | "loose"


def _labels(style: str) -> list[str]:
    if style == "upper":  return ["A", "B", "C", "D"]
    if style == "lower":  return ["a", "b", "c", "d"]
    if style == "parens": return ["(A)", "(B)", "(C)", "(D)"]
    raise ValueError(style)


def _join(options: list[str], labels: list[str], sep: str) -> str:
    entries = [f"{label} {opt}" for label, opt in zip(labels, options)]
    if sep == "newline":
        return "\n".join(entries)
    if sep == "comma":
        return ", ".join(entries)
    raise ValueError(sep)


def _instruction(phrase_key: str) -> str:
    # phrase_key is e.g. "answer_only: 'Answer:'" — split on the colon.
    return phrase_key.split(":", 1)[1].strip().strip("'\"")


def render(item: dict, cell: FormatCell, fewshot_items: list[dict]) -> str:
    gap = "\n\n" if cell.whitespace == "loose" else "\n"
    labels = _labels(cell.label_style)
    parts: list[str] = []

    for demo in fewshot_items[: cell.fewshot]:
        demo_opts = _join(demo["choices"], labels, cell.separator)
        parts.append(
            f"Question: {demo['question']}{gap}{demo_opts}{gap}"
            f"{_instruction(cell.instruction)} {labels[demo['answer_index']]}"
        )

    options = _join(item["choices"], labels, cell.separator)
    parts.append(
        f"Question: {item['question']}{gap}{options}{gap}"
        f"{_instruction(cell.instruction)}"
    )
    return gap.join(parts)
```

### 2.4 Score each cell

For each of the 72 cells, run the model on all 500 items and record the accuracy with a bootstrap 95% CI (10,000 resamples, seed pinned). The output is one row per cell:

```
cell_id, instruction_phrasing, option_label_style, option_separator, fewshot_count, whitespace, acc, acc_ci_low, acc_ci_high, n_items
```

Call this the **cell table** — it is the raw material for everything downstream.

### 2.5 Sensitivity decomposition

Three numbers summarize the cell table. All three must appear in the report.

**(a) Raw range.** `max(acc) - min(acc)` across all cells. A raw range above 5 percentage points is the threshold at which a single-format published number becomes misleading; a raw range above 10 points means the published number says more about the prompt than about the model.

**(b) Per-axis sensitivity.** For each axis, marginalize over all other axes and compute the max minus min of the mean accuracy per axis level. This answers: *which axis is the model most sensitive to?*

Example rows from the summary:

```
Axis                    Levels                           Marginal accs           Per-axis range
instruction_phrasing    [answer_only, pick_one, best]    [0.74, 0.73, 0.69]     0.05
option_label_style      [upper, lower, parens]           [0.74, 0.70, 0.73]     0.04
option_separator        [newline, comma]                 [0.74, 0.70]           0.04
fewshot_count           [0, 5]                           [0.65, 0.79]           0.14
whitespace              [tight, loose]                   [0.73, 0.72]           0.01
```

In this worked example, `fewshot_count` is the dominant axis (0.14) and whitespace is noise (0.01). That is the actionable finding.

**(c) Item-vs-format variance decomposition.** For each (item, cell) pair, record the model's binary score. Then fit a two-way ANOVA (or a random-effects model if the learner knows to do so) with factors `item_id` and `cell_id`. Report `σ²_format / (σ²_item + σ²_format + σ²_residual)` as the fraction of score variance attributable to format. If it is above ~10%, the format is doing non-trivial work; above 25% and the published single-format number is a vibe check, not a measurement.

A simple proxy that learners can compute without a stats package: **item-level flip rate** — the fraction of items whose binary score differs between the best-performing cell and the worst-performing cell. A flip rate above 20% is the "lots of items change category purely from formatting" signal.

### 2.6 Report shape

`REPORT.md`:

```
# Prompt-format sensitivity — <model>@<revision> — <task> — 2026-11-13

## 1. Headline
raw range (max - min) across 72 cells: 0.14  (0.65 .. 0.79)
dominant axis: fewshot_count (per-axis range 0.14)
item-level flip rate (best cell vs. worst cell): 0.24
variance-share attributed to format: 0.17

## 2. Verdict
"Publish as: baseline = 0.72 (±0.07 format band, 95% CI); fewshot_count
drives most of the band; whitespace is noise." OR
"Block single-format publication: dominant axis moves the number by 14 pp;
report a band and the per-axis sensitivity, not a single number."

## 3. Cell table         (72 rows)
## 4. Per-axis sensitivity  (5 rows)
## 5. Attachments
- formats/axes.yaml
- formats/render.py   (prompt renderer)
- cells/*.jsonl       (per-cell per-sample outputs)
- bootstrap_ci.json
```

The verdict is a single sentence, by design. Readers paste it. If it is a paragraph, nobody uses it.

### 2.7 Decision rules

The diagnostic produces a verdict against three thresholds that must be committed *before* the run:

- **Raw range ≤ 5 pp** → publish a single-format number; sensitivity is below the noise floor.
- **5 pp < raw range ≤ 10 pp** → publish `baseline (±band)` with the band equal to the raw range; call out the dominant axis.
- **Raw range > 10 pp** → do not publish a single number. Publish the per-axis table; treat the model's score on this task as prompt-sensitive and require the deployment team to pick a format and justify it.

Thresholds are illustrative defaults. Commit the thresholds in a `policy.yaml` so later runs do not negotiate the standard.

## 3. Validation steps

1. **Render roundtrip.** On three sample items, render all 72 cells and print the full prompt for cell 0, cell 36, and cell 71. A reviewer must confirm these three look like three distinct prompts of the same question. If they look identical, the matrix is collapsing.
2. **Determinism.** Re-run the whole diagnostic with the same seeds; the cell table must match to the last digit.
3. **Item-identity check.** Across cells, the set of item ids scored must be identical. If a cell drops items (e.g., because it exceeds a context-length budget), that is a confound; either shrink the fewshot_count level or drop the item uniformly across all cells.
4. **Bootstrap CI sanity.** Point estimates must sit inside their CIs; the CIs must be computed from the per-item scores in the cell outputs, not from a formula.
5. **Dominant-axis stability.** Recompute the per-axis sensitivity on a random 250-item subsample of the 500 items; the dominant axis must be the same. If it is not, the diagnostic is underpowered — raise the item count.
6. **Policy threshold applied, not negotiated.** The verdict sentence must reference the committed thresholds from `policy.yaml`, not a threshold chosen after seeing the raw range.
7. **Attack-surface cross-check.** Pick one axis level that is a plausible attacker rewrite (e.g., `pick_one` → `pick one`). If the model's accuracy moves more than 5 pp on this benign rewrite, that is the signal an attacker needs to craft a worse one; log it as an adversarial follow-up, not a happy variance.

## 4. Rubric

Scored out of 10. The rubric rewards the diagnostic being **decisive** — it produces a shipping decision, not a chart.

| # | Criterion | Points | Passing evidence |
|---|---|---|---|
| R1 | Format matrix is committed with named axis levels | 1 | `formats/axes.yaml` lists ≥ 4 axes; every level is a named string. |
| R2 | Prompt renderer is a committed pure function | 1 | `formats/render.py` is a module, not a notebook cell; the same (item, cell) pair produces the same prompt bit-for-bit. |
| R3 | Items are fixed across cells | 1 | Every cell scores the same item set, same order, same seed. |
| R4 | Cell table reports per-cell accuracy + bootstrap CI | 2 | 72 rows with `acc`, `acc_ci_low`, `acc_ci_high`; CIs computed from per-item scores, not formulas. |
| R5 | Per-axis sensitivity table is present | 2 | 5 rows (one per axis) with marginal accs and the per-axis range. |
| R6 | Item-level flip rate or variance-share is reported | 1 | A measure of "format moves individual items" is in the headline. |
| R7 | Verdict sentence references the committed thresholds | 1 | The verdict names the band and dominant axis, and cites `policy.yaml`. |
| R8 | Thresholds were committed before the run | 1 | `policy.yaml` predates `cells/` in the git history. |

**Passing bar:** 7 / 10. Below that, the diagnostic is a chart; above, it is a control.

### Review checklist (for a maintainer)

- [ ] The matrix is small enough that a reviewer can read every row.
- [ ] No cell silently drops items (e.g., because of context-length overflow).
- [ ] Bootstrap seed is pinned.
- [ ] The dominant axis matches between the full run and a half-size resample.
- [ ] The verdict sentence is pasteable.
- [ ] A policy file commits the publish / band / refuse-to-publish thresholds.

## 5. Common mistakes

- **Reporting only one number.** A single-format score on a format-sensitive task is a misleading result. If the raw range is more than a couple of points, the number needs a band.
- **Picking the "best" format and reporting its number.** This is `argmax` over prompts, which is overfitting disguised as evaluation. Pick the format on a *held-out* axis or report the band.
- **Testing dozens of axes.** Eight axes with three levels each is 6,561 cells. Nobody reads that. Pick four to six axes; crossing them is the point.
- **Changing more than one thing per cell.** If the rendered prompt differs in two axes between adjacent cells, the sensitivity decomposition is wrong.
- **Letting fewshot items vary across cells.** The fewshot demo items must be the same (and in the same order) across all cells that include fewshot; otherwise the axis is "fewshot items" not "fewshot_count."
- **Silent context-length truncation.** Some cells (e.g., `fewshot=5` + `loose whitespace`) may exceed the context budget on long items. Truncation changes the item set; the diagnostic must either reject the item uniformly or raise an error, not silently drop.
- **Negotiating the thresholds after seeing the result.** The verdict is only meaningful if the thresholds predate the cell table.
- **Treating low sensitivity as "the model is robust."** Low sensitivity on *these* axes is evidence of robustness to *these* perturbations only. It is not immunity to prompt attacks; it is a baseline.
- **Collapsing the band in the published number.** "Accuracy 0.72" without the ±band hides the band. Publish both or publish neither.
